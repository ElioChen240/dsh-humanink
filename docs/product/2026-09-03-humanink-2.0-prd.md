# HumanInk 2.0 产品需求文档

**日期：** 2026-09-03
**目标版本：** 0.9.0 MVP
**产品定位：** 集成在 DeepSeek Harness 中的本地 AI 内容生产工作台。

## 1. 背景与问题

HumanInk 现有版本已经具备标题生成、简报、大纲、初稿、人味化改写、复核、版本链、异步任务和 DSH Bundle，但客户端体验仍偏向“嵌入的独立工具”，没有形成 DSH 对话、当前内容、Agent 工具和本地文件之间的统一上下文。

2.0 重构不推翻已有稳定能力，重点解决：

- UI 与 DSH Shell、会话上下文割裂；
- 文章主要按内部项目与版本展示，用户难以直接理解磁盘产物；
- Agent 不知道用户当前正在处理哪篇文章；
- 可选能力失败时缺少统一的能力状态和局部降级；
- Client、Host 和 DSH 版本兼容边界不够清晰。

## 2. 产品原则

1. **内容归用户所有**：正式内容以普通目录和 Markdown/JSON 文件保存。
2. **Human in the loop**：AI 提案、用户确认、写入新版本，不静默覆盖正式稿。
3. **Agent-first**：UI、Tool、Skill、System Prompt 和当前文章引用共享同一应用服务。
4. **本地优先**：核心写作闭环不依赖外部发布平台。
5. **局部降级**：缺少搜图、封面、检测等可选能力时，标题、写作、改写和版本管理仍可使用。
6. **可验证完成**：任务返回成功且产物落盘后，才能显示为完成。
7. **Windows 一等支持**：路径、子进程、换行和打包测试必须覆盖 Windows。

## 3. 目标用户

- 需要持续生产中文文章的自媒体创作者；
- 需要在 AI 初稿基础上保留个人表达的编辑；
- 希望在 DSH 对话中完成创作，同时保留本地稿件和版本历史的用户。

## 4. MVP 用户闭环

```text
进入 DSH
→ 打开 HumanInk 内容侧栏
→ 新建内容项目
→ 输入主题或粘贴原文
→ 生成并选择标题
→ 生成简报/大纲/初稿，或原创改写
→ 在内容检查器编辑
→ 执行中文自然化
→ 查看修改摘要和风险提示
→ 保存新版本
→ 导出 Markdown
```

用户还可以在对话中引用当前内容：

```text
把 @文章：普通人如何建立自己的 AI 工作流 的开头改得更自然。
```

## 5. MVP 功能范围

### 5.1 内容库

- 选择和初始化内容根目录；
- 扫描文章目录并展示标题、阶段、更新时间和当前版本；
- 新建、搜索、筛选和刷新内容；
- 文件变更后刷新 revision；
- 不在 MVP 中删除用户目录。

### 5.2 写作工作流

- 爆款标题候选；
- 内容简报；
- 大纲；
- Markdown 初稿；
- 根据原文进行原创改写；
- 中文自然化改写；
- 发布前复核；
- 每次 AI 写入均生成新版本。

### 5.3 编辑与版本

- Markdown 编辑；
- 预览；
- 当前稿保存为新版本；
- 查看版本列表；
- 从历史版本恢复为新版本；
- 导出 Markdown；
- 显示字数、来源、生成方式和创建时间。

### 5.4 DSH 集成

- 使用 DSH 官方 Slot 注册 HumanInk 内容入口；
- 内容检查器按选择动态挂载，不默认占满 Shell；
- Host/Client 通过有 schema 的 Remote Contract 通信；
- 注册 Runtime Skill、Tools、System Prompt 和 `@文章`触发器；
- 所有生成请求继续通过 Harness LLM 服务，不自行读取 API Key。

### 5.5 能力状态

统一状态：

```text
ready | missing | unsupported | error
```

MVP 检测：

- 内容目录；
- Harness LLM；
- 文件读写；
- DSH Client Remote；
- 可选 Credentials 服务。

## 6. 非 MVP 范围

以下能力保留接口和产品位置，但不在 0.9.0 中实现：

- 自动搜图和版权筛选；
- AI 封面生成；
- 腾讯朱雀网页自动检测；
- 自动搜选题和热点采集；
- 多平台自动发布；
- 发布数据回收；
- 团队协作、云同步和商业计费。

## 7. 信息架构

### 左侧：内容导航

- 会话 / 内容切换；
- 内容搜索与阶段筛选；
- 新建内容；
- 内容列表；
- 设置入口。

### 中间：内容检查器

- 项目概览；
- Markdown 编辑/预览；
- 版本历史；
- AI 操作；
- 任务状态；
- 修改摘要与复核结果。

### 右侧：DSH 对话

- 保持 Harness 原生对话；
- 自动注入当前内容摘要；
- 支持 `@文章`明确引用；
- Agent 调用 HumanInk Tools 推进工作流。

## 8. 文件约定

```text
<libraryRoot>/
└── 2026-09-03_文章标题/
    ├── brief.md
    ├── outline.md
    ├── article.md
    ├── metadata.json
    ├── references.json
    ├── versions/
    │   ├── v0001.md
    │   └── v0002.md
    ├── images/
    └── covers/
```

插件附加状态保存在 DSH 数据目录下的 HumanInk 子目录，不保存正文副本。UI 偏好只保存选中项、筛选条件和面板宽度。

## 9. 成功指标

MVP 验收必须同时满足：

- 新用户安装后可在 DSH 中找到 HumanInk；
- 不依赖 Better Sidebar 也有可用入口；
- 能完成“新建→生成/改写→编辑→自然化→保存版本→导出”闭环；
- UI 和 Agent 对同一内容项目读写；
- DSH 重启后内容、版本和任务结果仍可恢复；
- 缺少可选能力时核心闭环不失败；
- Windows 下类型检查、测试、构建和 Bundle 契约通过；
- README 明确当前可用功能与规划功能。

## 10. 交付边界

0.9.0 是架构重构 MVP，不以功能数量为目标。旧命令在一个兼容周期内保留；旧项目数据通过适配器读取，不做破坏性迁移。任何删除旧入口或数据格式的工作必须单独设计并获得确认。
