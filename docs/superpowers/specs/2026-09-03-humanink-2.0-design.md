# HumanInk 2.0 DSH 原生内容工作台设计

**日期：** 2026-09-03
**状态：** 待用户书面审阅后进入实现

## 1. 决策

采用“保留核心、替换集成层”的渐进重构：

- 保留 `@humanink/core`、`@humanink/storage`、现有任务与版本能力；
- 新建统一 Workbench Service；
- 以 DSH 官方 Slot + Remote + Tool + Skill + Prompt 形成闭环；
- Better Sidebar 降级为可选增强；
- 0.9.0 只交付核心写作闭环，不加入搜图、封面、朱雀、热点和发布。

## 2. 备选方案

### A. 渐进重构（采用）

风险最低，可持续复用 198+ 既有测试和数据格式；代价是一个版本内存在新旧 Adapter。

### B. 完整重写

结构最干净，但会同时重写领域、存储和 UI，回归风险及交付周期不可控。

### C. 继续修补现有 Better Sidebar UI

短期快，但无法解决 Agent 上下文、能力降级和 Remote 契约问题，继续积累耦合。

## 3. MVP 设计

- 内容项目映射到用户可编辑的 Markdown 目录；
- 当前选中内容驱动中间检查器与右侧 Agent 上下文；
- 命令、Tools 和 Client Remote 共用 Workbench Service；
- AI 输出写入新版本；
- 任务成功以文件产物和 metadata 提交为准；
- 所有可选能力通过 Capability Report 呈现；
- Windows 为发布阻断平台。

## 4. 兼容边界

- 不删除旧命令；
- 不破坏旧项目读取；
- 不默认禁用官方侧栏；
- 不强依赖 Better Sidebar；
- 不在 Core 中导入 DSH 类型；
- 不在 Client 保存正文；
- 不让 API Key 进入对话或项目目录。
