# HumanInk dsh Web 工作台设计

**日期：** 2026-09-02
**目标版本：** 0.7.0

## 1. 目标

在 DeepSeek Harness 的 `dsh web` 中提供正式 HumanInk 内容工作台，而不是独立静态 Demo。UI 与现有 `/humanink-*` 命令复用同一应用服务、JSONL 数据和异步任务运行时，命令能力保持兼容。

## 2. 第一版范围

- 项目列表、新建文章与版本历史；
- 输入主题或原始内容，生成并选择标题；
- 生成简报、大纲和初稿；
- 正文编辑、Markdown 预览、保存为新版本；
- 人味化改写与发布前复核；
- 任务状态、取消、失败提示；
- Markdown 复制与导出。

本版本不包含搜图、AI 封面、自动选题、腾讯朱雀检测和平台发布。

## 3. 接入方式

- Browser 半侧通过包的 `./client` 导出加载；
- 在 `sidebar.footer.action` 注册 HumanInk 入口；
- 点击入口打开 `shell.overlay` 全屏工作台；
- 不修改 Harness 私有 DOM，不 fork Shell；
- Host 半侧暴露框架无关的 UI facade；Browser 侧通过隔离的 transport adapter 调用，便于在官方 RPC 接口变化时单点调整。

## 4. 信息架构

### 左栏：内容导航

- 新建文章；
- 项目列表与搜索；
- 当前项目版本历史；
- 版本切换和恢复入口。

### 中栏：编辑器

- 标题输入；
- Markdown 编辑 / 预览 / Diff 标签；
- 保存状态；
- 复制与导出；
- 当前版本、字数和来源信息。

### 右栏：AI 创作流程

- 标题候选；
- 简报、大纲、初稿；
- 人味化改写；
- 发布前复核；
- 活跃任务状态与取消。

## 5. 核心规则

1. AI 生成和用户保存都创建新版本，不静默覆盖现有版本。
2. 切换历史版本只改变查看上下文；恢复时创建 `restored` 版本。
3. 复核只提供问题、风险和建议，不自动发布。
4. Host facade 复用现有 `HumanInkApplication`、仓储和任务运行时，不复制领域逻辑。
5. UI 通过可注入 API 接口运行；测试使用内存 fake，不依赖真实浏览器宿主。
6. 视觉采用纸墨紫编辑部风格：低饱和底色、清晰层级、克制阴影、正文优先。

## 6. 验收标准

- 安装 Bundle 后，Browser client 能注册侧边栏入口和全屏 Overlay；
- 用户可在 UI 中完成“新建 -> 查看/编辑 -> 保存新版本 -> 触发 AI 任务 -> 查看状态 -> 导出”的闭环；
- UI 与命令共用数据，不新增第二套持久化格式；
- Client、Host 单元测试、类型检查、构建和 Bundle 打包通过；
- 若本机缺少可运行的 `dsh web`，必须将真实宿主浏览器验收标记为环境阻塞。
