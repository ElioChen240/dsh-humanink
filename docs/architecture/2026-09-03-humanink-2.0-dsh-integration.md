# HumanInk 2.0 DeepSeek Harness 集成协议

**日期：** 2026-09-03
**目标：** 让 HumanInk 成为 DSH 原生内容能力，而不是独立网页。

## 1. 集成原则

1. 不修改 DSH 私有 DOM；
2. 不以 Better Sidebar 为硬依赖；
3. 不默认替换整个官方侧栏；
4. 使用官方 Slot、Remote、Settings、Locale、Credentials 和 Tool 服务；
5. 插件卸载时完整释放所有 Slot、Remote、轮询和订阅；
6. Host 功能可在无 Client 的命令模式运行。

## 2. Host 生命周期

```ts
export const name = "dsh-humanink";

export function apply(ctx: Context, config: Config): () => void {
  const service = createWorkbenchService(ctx, config);
  const disposers = [
    registerRemote(ctx, service),
    registerTools(ctx, service),
    registerRuntimeSkill(ctx, service),
    registerSystemPrompt(ctx, service),
    registerSettings(ctx, service),
  ];
  return () => disposers.reverse().forEach((dispose) => dispose());
}
```

`apply()` 必须返回合法 disposer，不返回普通实例对象。可选服务使用防御式检测，缺失时不能让 Cordis fiber 永久 pending。

## 3. Client Slot 策略

### 基础入口

始终注册官方可用的轻量入口，例如 `sidebar.footer.action`。点击后选择当前内容或打开设置。

### 内容导航

优先注册官方可扩展的 sidebar slot；若宿主允许自定义 sidebar occupant，则提供“会话 / 内容”切换，但 MVP 不禁用 `ui-sidebar`。

### 内容检查器

- selectedContentId 非空时注册 `shell.overlay`；
- 取消选择时卸载；
- overlay 不默认弹出；
- 保留 DSH 对话区域；
- 面板宽度持久化但限制最小/最大值。

### Better Sidebar

若检测到 Better Sidebar：

- 可注册 `humanink:workbench` Tab；
- 同一个 Client 实例只注册一次；
- 插件卸载/HMR 时注销；
- Better Sidebar 异常时立即降级到官方入口。

## 4. Remote Contract

MVP invocation：

```text
listContents
getContent
createContent
saveVersion
startAction
getTask
cancelTask
getCapabilities
getRevision
getSettings
setLibraryRoot
setWritingProfile
```

所有输入输出由 Zod schema 定义。错误统一为：

```ts
interface RemoteError {
  code: "INVALID_INPUT" | "NOT_FOUND" | "CONFLICT" | "CAPABILITY_MISSING" |
        "LLM_PROVIDER_FAILED" | "STORAGE_FAILED" | "TASK_FAILED" | "INTERNAL";
  message: string;
  retryable: boolean;
  detail?: Record<string, unknown>;
}
```

Remote 层不暴露 Node Error、绝对凭据路径和模型密钥。

## 5. Tools

MVP 工具：

```text
humanink_guide
humanink_setup
humanink_list_contents
humanink_get_content
humanink_create_content
humanink_generate_titles
humanink_write_draft
humanink_rewrite_content
humanink_humanize_content
humanink_review_content
humanink_get_task_status
```

规则：

- 读取类工具可直接执行；
- 配置变更默认 preview，只有用户确认后 apply；
- AI 写作默认生成新版本；
- Tool 只报告“任务已启动”或“产物已完成”，不能混用；
- 输出卡片展示 contentId、taskId、状态和下一步。

## 6. Runtime Skill

Skill 名称：`humanink-workbench`。

必须指导 Agent：

- 不知道下一步时先调用 `humanink_guide`；
- 首次使用先只读诊断 `humanink_setup`；
- 不要求用户把 API Key 发到对话；
- 明确区分新建写作与基于原文的原创改写；
- 不覆盖正式稿，生成结果保存为新版本；
- 每次只推进当前缺失步骤；
- 长任务启动后查询状态；
- 未验证文件产物前不声称完成。

## 7. System Prompt 上下文

只注入紧凑摘要：

- HumanInk 可用能力；
- 当前选择的 contentId、标题、阶段和版本；
- 当前任务状态；
- 用户写作 profile 摘要；
- 内容文件位置的逻辑标识，不注入密钥。

正文默认不整篇注入；只有用户明确引用、Tool 获取或任务需要时加载，以控制上下文长度。

## 8. `@文章`触发器

显示格式：

```text
@文章：<标题>
```

解析结果包含：

```ts
interface ContentMention {
  type: "humanink-content";
  contentId: string;
  title: string;
  versionId: string;
}
```

触发器通过 Remote 搜索内容，选中后向对话添加结构化 mention，不粘贴全文。

## 9. Revision 同步

- Host 对内容目录和任务状态维护单调递增 revision；
- Client 可使用低频轮询作为兼容方案；
- 面板可见时轮询，隐藏时暂停；
- revision 变化后只刷新摘要，选中详情按需刷新；
- 后续 DSH 支持事件流时可替换轮询，Client 状态接口保持不变。

## 10. DSH 版本验证矩阵

任何依赖升级前记录并验证：

| 项目 | 验证内容 |
|---|---|
| Host apply | disposer、注入生命周期、无 pending fiber |
| Client loader | `./client` 可加载、CJS closure 形状正确 |
| Slots | 注册、卸载、HMR、缺失降级 |
| Remote | mount、schema、错误序列化 |
| Tools | 调用、取消、输出渲染 |
| Credentials | 只读状态、Host 侧使用、不回显 |
| Desktop | 启动、入口可见、内容选择、任务结果刷新 |

MVP 实现前先针对用户当前 DSH Desktop 建立契约测试，不能直接复制其他插件的 RC 版本声明。
