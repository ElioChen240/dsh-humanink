# HumanInk 2.0 技术架构参考

**日期：** 2026-09-03
**状态：** 0.9.0 MVP 架构基线

## 1. 架构目标

保留现有 Core、Storage、Harness 的稳定能力，重写 Client UI 和 DSH 集成边界。领域逻辑不依赖 DSH RC API，DSH 变化只影响 Adapter。

## 2. 分层

```text
packages/humanink-core
  领域类型、标题、写作、改写、复核、版本规则

packages/humanink-storage
  文件项目仓库、overlay、原子写入、目录扫描

packages/humanink-harness
  应用服务、任务运行时、Tools、Skill、Prompt、Remote Host

packages/humanink-client
  DSH Slots、内容侧栏、内容检查器、设置和 Remote Client
```

依赖只能向内：

```text
client ──┐
         ├→ application ports → core
harness ─┘                    ↘ storage adapters
```

Core 不导入 React、Cordis、DSH Remote 或 Node 文件系统实现。

## 3. 应用服务边界

新增统一的 `HumanInkWorkbenchService`，供命令、Tool 和 Remote 共用：

```ts
interface HumanInkWorkbenchService {
  listContents(input: ListContentsInput, signal?: AbortSignal): Promise<ContentSummary[]>;
  getContent(id: string, signal?: AbortSignal): Promise<ContentDetail>;
  createContent(input: CreateContentInput, signal?: AbortSignal): Promise<ContentDetail>;
  saveVersion(input: SaveVersionInput, signal?: AbortSignal): Promise<ContentVersion>;
  startAction(input: StartActionInput, signal?: AbortSignal): Promise<HumanInkTask>;
  getTask(id: string, signal?: AbortSignal): Promise<HumanInkTask>;
  getCapabilities(signal?: AbortSignal): Promise<CapabilityReport>;
  getRevision(signal?: AbortSignal): Promise<number>;
}
```

现有 `HumanInkApplication` 暂时作为底层能力保留，由 Workbench Service 编排，不在 Client 中复制业务逻辑。

## 4. 存储模型

### 内容真源

- 正文、简报、大纲和历史版本：普通 Markdown 文件；
- 元数据：带 schemaVersion 的 JSON；
- 写入：同目录临时文件后原子 rename；
- Windows 文件替换失败时使用受控重试，不跨目录移动临时文件。

### Overlay

仅保存：

- 手动阶段覆盖；
- 当前正式版本；
- 任务引用；
- 会话绑定；
- UI 无法从文件推断的状态。

Overlay 按 dataDir 串行写入，采用白名单解码，未知字段在兼容读取时忽略。

### UI persistence

`localStorage` 仅保存：

- selectedContentId；
- sidebarTab；
- query/filter；
- inspectorWidth；
- editorView。

## 5. 任务模型

```ts
type TaskStatus = "queued" | "running" | "succeeded" | "failed" | "cancelled";

interface HumanInkTask {
  id: string;
  contentId: string;
  action: "titles" | "brief" | "outline" | "draft" | "rewrite" | "humanize" | "review";
  status: TaskStatus;
  startedAt?: string;
  finishedAt?: string;
  outputVersionId?: string;
  error?: { code: string; message: string; retryable: boolean };
}
```

成功判定：模型调用成功、输出校验通过、版本文件完成原子写入、metadata 指针更新。缺一不可。

## 6. 能力检测

`CapabilityService` 统一返回：

```ts
interface CapabilityState {
  state: "ready" | "missing" | "unsupported" | "error";
  reason?: string;
  action?: string;
}
```

Client 不自行猜测 Host 能力。按钮是否可用、错误提示和设置引导全部由报告驱动。

## 7. 兼容策略

- 保留 `/humanink-*` 命令至少一个 Minor 版本；
- 保留现有任务存储读取能力；
- 新文件仓库通过 Adapter 映射到 Core `ContentProject`；
- Client 不直接调用旧 `/humanink` RPC；
- 若目标 DSH 缺少 Typert Remote，则由 Remote Adapter 降级到现有 Connection Transport；
- Better Sidebar 只作为可选增强，不是启动依赖。

## 8. 模块拆分建议

```text
packages/humanink-harness/src/
  application/workbench-service.ts
  capabilities/capability-service.ts
  remote/contract.ts
  remote/host.ts
  tools/register.ts
  tools/*.ts
  skills/workbench-skill.ts
  prompts/library-prompt.ts

packages/humanink-client/src/
  plugin.ts
  remote/client.ts
  sidebar/HumanInkSidebarRoot.tsx
  sidebar/ContentSidebarPanel.tsx
  inspector/ContentInspector.tsx
  inspector/*.tsx
  settings/HumanInkSettingsCard.tsx
  persistence.ts
```

限制：单个业务组件建议不超过 350 行；单个 Service 不超过 500 行。超过时按领域动作拆分。

## 9. 安全

- API Key 不进入对话、Tool 参数、项目文件、日志或 localStorage；
- 使用 Harness Credentials Service；
- 错误信息去除 Authorization、Key、Token 和堆栈中的敏感片段；
- 文件操作限定在解析后的 libraryRoot 内；
- 不跟随逃逸 libraryRoot 的符号链接；
- 不自动删除用户内容。

## 10. 测试策略

- Core：纯函数和领域规则；
- Storage：Windows 路径、原子写入、恢复、目录逃逸；
- Harness：Service、Tool、Skill、Prompt、Remote Contract；
- Client：Slot 生命周期、选择同步、能力降级、错误边界；
- Bundle：Host/Client 入口、Patch、tarball 内容；
- DSH Desktop：最小真实宿主冒烟清单。

每项任务先写失败测试，再实现；完成前运行最小相关测试和完整 `pnpm test/typecheck/build`。
